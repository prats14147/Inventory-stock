# Data

## `raw/retail_store_inventory.csv`

Source dataset. **73,100 rows, 15 columns.** Do not edit this file by hand —
all cleaning happens in `scripts/clean_data.py` and writes to `processed/`.

| Column | Notes |
|---|---|
| Date | 2022-01-01 to 2024-01-01 |
| Store ID | 5 unique stores |
| Product ID | 20 unique products |
| Category | Furniture, Toys, Clothing, Groceries, Electronics |
| Region | 4 unique regions |
| Inventory Level | >= 0 |
| Units Sold | >= 0 |
| Units Ordered | >= 0 |
| Demand Forecast | Existing forecast column from the source data — **not** used as a
model feature (would leak the thing we're trying to predict); 673 rows
(~0.92%) are negative and are clipped to 0 during cleaning |
| Price | >= 0 |
| Discount | 0-100 |
| Weather Condition | categorical |
| Holiday/Promotion | 0 or 1 |
| Competitor Pricing | numeric |
| Seasonality | categorical |

`Units Ordered` is the source dataset's recorded order quantity for that
date/store/product row. It is not on-hand stock (use `Inventory Level`),
and the source does not include a supplier name or order status.

## Known data-quality findings (from initial inspection)

- 0 missing values, 0 duplicate rows.
- `(Date, Store ID, Product ID)` is unique across all rows.
- 369 rows (~0.505%) have `Units Sold >= Inventory Level`. These are **not**
  automatically treated as confirmed stockouts — they may reflect exact
  demand/inventory matches or demand-censored sales. See
  `docs/limitations.md` (added in a later phase) for the full discussion.
